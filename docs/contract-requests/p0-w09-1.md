# Contract request p0-w09-1: forget the preview limiter on test reset

**Status:** applied by the contract steward (additive, wiring only).

**From:** P0-W09 · **Kind:** additive (wiring in `gate/wire`, scaffold-owned)

## Why

`gate/previews` keeps its per-host fetch limiter (1 request per 2 s per registrable domain,
burst 3) in memory (plan §3.2 "not stored"), keyed by host and timed by the App's clock. In an
e2e run the clock is the fake clock behind `/api/_test/clock`, and every spec serves its pages
from `127.0.0.1`, so the buckets of one spec would still be empty in the next and its previews
would fail as rate-limited. `Hooks.Reset` (`/api/_test/reset`) truncates `link_previews` and
`link_fetch_cache` with every other table; it should leave no limiter state behind either,
exactly as a restart would.

## Diff

`internal/gate/wire/hooks.go`, in `Reset`, next to `h.a.Tree.Reset()`:

```go
h.a.Previews.Reset()
```

`(*previews.Service).Reset` drops every limiter bucket. Nothing else in the previews module is
held in memory.
