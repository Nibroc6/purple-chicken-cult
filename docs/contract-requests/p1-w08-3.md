# Contract request p1-w08-3: a race in the INT-0 unfriending journey

**Status:** applied by the contract steward (test-only) after the P1-W08 work commits.

**From:** P1-W08 · **Kind:** test-only, in a file INT-1 owns
(`web/e2e/journeys/horizon.spec.ts`) · **Implementer:** contract steward

## Why

"Unfriending takes effect on the next request, even inside an open feed session" failed
on CI for the P1-W08 PR (both locales, with retries). Locally it fails about one run in
six. The spec waited for `action-unfriend` to disappear as a
sign that the unfriend was done. But the confirm step replaces that button at once, so the
wait passed before `DELETE /api/friends/{ref}` was answered. Since P1-W03 the action also
first asks whether the session co-signs, which widened the gap. The spec then closed the
tab and loaded the next feed page. When that page was served before the unfriend
committed, alice's posts were still there. The product behaves as specified: the graph
edge is removed synchronously in the unfriend request.

## Diff

`horizon.spec.ts`: the spec waits for the `DELETE /api/friends/…` response (and checks
that it succeeded) before closing the tab. The assertions are unchanged. 16 of 16
repeated runs pass with no retries (before the fix: 1 of 6 failed).
