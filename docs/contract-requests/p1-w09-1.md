# Contract request p1-w09-1: GET /api/me/theme, and Explorer in the format picker

**Status:** applied by the contract steward before the P1-W09 work commits.

**From:** P1-W09 · **Kind:** additive (one catalogue route, one more allowed `ui_prefs.format`
value) in steward-owned and P1-W10-owned files · **Implementer:** contract steward

## Why

1. **Reading the theme back.** The plan gives themeapi `PUT /api/me/theme` → `{theme}` and
   `DELETE /api/me/theme` only. The client applies the reader's theme on every load and on
   every device (preferences live server-side, §15.1), so it needs to read it: the theme
   lives in its own table (`user_themes`), not in `MeView`, and adding it to `MeView` would
   touch the account view P1-W10 is building in parallel. A `GET /api/me/theme` on the
   themeapi module is the smallest change: the caller's own row, free like `GET /me`
   (`{theme}`; absent for the default).
2. **Explorer reachable.** `gate/account.Formats` carries the comment "P1 adds explorer"; the
   settings page and `toUIPrefs` mirror it. P1-W09 ships the Explorer format, so the value
   becomes valid and the Display page offers it.
