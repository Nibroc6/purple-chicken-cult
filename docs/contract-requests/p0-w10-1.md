# Contract request p0-w10-1: close the SSE streams and forget pending metrics on test reset

**Status:** applied by the contract steward (additive, wiring only).

**From:** P0-W10 · **Kind:** additive (wiring in `gate/wire`, scaffold-owned)

## Why

`gate/notify` keeps the open `/api/events` streams in memory, keyed by user ID and session,
and `gate/metrics` keeps the counters of the current minute in memory until `metrics.flush`.
`Hooks.Reset` (`/api/_test/reset`) truncates every table with `RESTART IDENTITY`, so the next
spec of the same e2e run reuses the same user IDs for new accounts. A stream left open by the
previous spec would then receive the new account's `notification{unread}` pings and live
events (a different person's), and leftover counters would be flushed into a
`metrics_daily` that belongs to a world that no longer exists. A reset should leave no
notification or metrics state behind, exactly as a restart would.

## Diff

`internal/gate/wire/hooks.go`, in `Reset`, next to the other in-memory resets:

```go
h.a.Notify.Reset()
h.a.Metrics.Reset()
```

`(*notify.Service).Reset` closes every open stream (clients reconnect and get `hello`) and
drops pending pings; `(*metrics.Service).Reset` drops the unflushed counters.
