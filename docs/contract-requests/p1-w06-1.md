# Contract request p1-w06-1: quarantine penalties, removed-account marks, the unified queue item

**Status:** applied by the contract steward (additive) before the P1-W06 work commits.
`gate/invites` (P1-W02) carries a steward body for `Penalize`, `gate/views` (P1-W03) three
steward lines for the mark; their owners may restyle them. coreref: `MemInvites.Penalize`.

**From:** P1-W06 · **Kind:** additive (two new interfaces, two new `Deps` fields, optional
view fields and schemas, wiring)
**Implementers:** P1-W02 (`gate/invites`: `InvitePenalties`), P1-W06 (`gate/moderation`:
`RemovedMarks`) · **Callers:** P1-W06 (quarantine), P1-W03 (`gate/views` Person)

## Why

1. Invite-tree quarantine (§8): "the direct inviter's invites pause for 30 days; a second
   offense revokes invite privileges". `invite_budgets.paused_until`, `revoked` and
   `offenses` are P1-W02's columns (plan §3.4) and no interface changes them;
   `core.Probation.Reset` only resets the subtree's probation.
2. The "invited a removed account" mark (fidelity #19) is shown on the inviter to the users
   in the stored `viewers` bitmap only. Person views are built by `gate/views`;
   `removed_account_marks` is P1-W06's table, so views needs a read interface and the
   view a field.
3. The unified queue item (P1-W06 deliverables): a CSAM item shows the hold's match
   metadata (p1-w04-2: "the CSAM item view calls `d.CSAM.Hold`… never a PostView or media
   URL"), a two-person action names what awaits the second moderator (they co-sign the
   exact `ModAction`, but the queue must say which action it is), and claims are visible
   to every moderator. `gate.ModItem` and its schema are contract.

## Diff

`internal/gate/internal/core/p1.go`:

```go
type InvitePenalties interface {
	// first offense: paused_until = until; later: revoked. Returns offenses after this one.
	Penalize(ctx context.Context, tx store.Q, inviter UserID, until time.Time) (offenses int, err error)
}
type RemovedMarks interface {
	Marked(ctx context.Context, viewer, inviter UserID) bool
}
```

`internal/gate/internal/core/deps.go`: `InvitePenalties InvitePenalties; Marks RemovedMarks`
(Marks optional: nil = no marks). `internal/gate/wire/wire.go`: `d.InvitePenalties =
a.Invites; d.Marks = a.Moderation`. `coretest.NewMem`: `d.InvitePenalties = inv`.

`internal/gate/views.go`: `PersonView.InvitedRemoved bool` (`invited_removed,omitempty`);
`ModItem` gains `Claimed bool`, `Pending *ModPending`, `CSAM *CSAMHoldView`;
new `ModPending{Action, Reason, Mine, At, ReportRef}` and
`CSAMHoldView{MatchInfo, SourceURL, HeldAt, RetainUntil, ReportedAt, ReportRef, AccountHeld}`.
`api/openapi/_common.yaml`: the same fields and schemas.

Steward bodies: `(*invites.Service).Penalize` upserts `invite_budgets` (offenses + 1; the
first sets `paused_until`, later ones `revoked`) and publishes `UserChanged`;
`(*views.Service).Person` sets `InvitedRemoved` from `d.Marks.Marked(viewer, u)` (never on
the viewer's own view); `(*moderation.Service).Marked` is a stub until the work commits.

## How callers use it

* Quarantine confirmation (second moderator, one transaction):
  `Probation.Reset(subtree \ {root}, now+30d)` → `InvitePenalties.Penalize(root, now+30d)`
  → `quarantines` row.
* `gate/views` calls `Marks.Marked` for every person view other than the viewer's own;
  the web person page can show `invited_removed` (INT-1, `features/people`).
