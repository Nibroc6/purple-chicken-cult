# Contract request p1-w04-1: CSAM hold state for moderation, the held media on queue items, CDN purge config, post_media reads

**Status:** applied by the contract steward (additive) before the P1-W04 work commits.
`gate/media` (P1-W04) carries steward stub bodies for the new interface; W04 owns and
replaces them. coreref: `MemMedia` implements `CSAMHolds` (nothing is ever held there).

**From:** P1-W04 · **Kind:** additive (one interface, one `Deps` field, one optional struct
field, one nullable column, one config group, one reader in plan §3.4)
**Implementer:** P1-W04 (`gate/media`) · **Callers:** P1-W06 (moderation queue, `csam_report`)

## Why

1. The `csam_report` moderator action fills `csam_holds.report_ref` (plan P1-W04: "W04
   provides `core.Media`-side state changes it calls"), and the queue shows moderators the
   match metadata of a CSAM item, never the content (security #7). `csam_holds` is
   W04's table, so moderation needs an interface over it.
2. A CSAM queue item must name the held media: `ModQueueItem` has a subject user and post
   but no media, and `Summary` holds counts only. A preview image's subject post can
   carry several images, an uploader several holds.
3. Deleting media purges its CDN key (security #27). Purging is an external API
   (Cloudflare zone purge) and needs a zone and a token; config is scaffold-owned and
   unknown enum values must refuse to start (D20).
4. `GET /api/media/{ref}/url` checks that the viewer can see a post containing the media
   (plan §4.7), and a deleted post's media is deleted with it. Both need
   `post_media` (written by P1-W12) → post id; `core.Media.Attach` has no post id.

## Diff

`internal/gate/internal/core/p1.go`:

```go
type ModQueueItem struct {
	…
	Media uuid.UUID // CSAM items: the held media (mod_queue.subject_media); zero = none
}

type CSAMHold struct {
	Media uuid.UUID; SubjectUser UserID; SourcePost PostID; SourceURL string
	MatchInfo map[string]string; HeldAt, RetainUntil time.Time
	ReportedAt *time.Time; ReportRef string; AccountHeld bool
}
type CSAMHolds interface {
	Hold(ctx context.Context, media uuid.UUID) (CSAMHold, error)                    // ErrNotFound unless held
	Report(ctx context.Context, tx store.Q, media uuid.UUID, reportRef string) error // once; csam_already_reported
	ReleaseAccount(ctx context.Context, tx store.Q, media uuid.UUID) error         // false positive: lift the upload hold
}
```

`internal/gate/internal/core/deps.go`: `CSAM CSAMHolds`. `internal/gate/wire/wire.go`:
`d.CSAM = a.Media`. `coretest.NewMem`: `d.CSAM = m.Media`.

`internal/store/migrations/2008_mod_queue_media.sql`:
`ALTER TABLE mod_queue ADD COLUMN subject_media uuid REFERENCES media(id);`

`internal/platform/config`: `Config.CDN CDNConfig{Purge, ZoneID, APIToken}` from
`PCC_CDN_PURGE` (`cloudflare` | `none`/empty; anything else ⇒ `Load` fails),
`PCC_CDN_ZONE_ID`, `PCC_CDN_API_TOKEN` (`cloudflare` without both ⇒ `Load` fails). Not part
of `MediaEnabled()` (the edge cache TTL is capped at the URL lifetime); `gate/media` logs a
WARN at start in prod with an s3 store and no purge.

`docs/IMPLEMENTATION.md` §3.4: `post_media` gains the direct SQL reader `gate/media`
(read-only). §3.3 lists `2008`, §4.2 the CDN config, SCAFFOLD-1 the new interface.

## How callers use it (P1-W06)

* `Enqueue` gets `ModQueueItem{Source: ModSrcCSAM, Priority: 0, SubjectUser, SubjectPost
  (preview images), Media, Summary: {"csam_match": 1, "upload"|"preview": 1}}` in the
  transaction that writes `csam_holds`; write `Media` to `mod_queue.subject_media`.
* The queue view of a CSAM item calls `d.CSAM.Hold(ctx, item.subject_media)` and shows
  `MatchInfo`, `SourceURL`, `HeldAt`, `RetainUntil`, `ReportedAt`/`ReportRef` and
  `AccountHeld`, never a `PostView` or a media URL.
* `POST /api/mod/items/{id}/csam-report {report_ref}` (two-person): on the second
  moderator's confirmation, `d.CSAM.Report(ctx, tx, media, reportRef)` in the
  confirmation's transaction. A false positive resolved by two moderators may call
  `ReleaseAccount` (the evidence stays until `RetainUntil`).
