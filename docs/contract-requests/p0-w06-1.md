# Contract request p0-w06-1: reload the engagement caches on test reset

**Status:** applied by the contract steward (additive, wiring only).

**From:** P0-W06 · **Kind:** additive (wiring in `gate/wire`, scaffold-owned)

## Why

`gate/engage` keeps the likers of every window post as roaring bitmaps in memory (plan §4.7
engage; window posts preloaded, older posts in an LRU loaded on demand). `Hooks.Reset`
(`/api/_test/reset`) truncates `engagements` but reloads only the users cache, the post index
and the graph. A reset that is not followed by a seed (devseed's `apply` already reloads
`d.Engage` through its `Load`) leaves cached liker sets in memory for posts that no longer
exist, so like counts, `LikedByMe` and network preference `n` could read stale data in the
next spec of the same run. The coreref stub never cached anything, so nothing exercised the
gap before W06.

## Diff

`internal/gate/wire/hooks.go`, in `Reset`, after the post index load (engage's `Load` walks the
post index window) and before the graph load:

```go
if err := h.a.Engage.Load(ctx); err != nil {
	return err
}
```

`(*engage.Service).Load` forgets every cached liker set and preloads the likers of the window
posts from `engagements`. Seen, hides and show-less live only in Postgres, so nothing else
needs a reload. coretest keeps `coreref.MemEngage` for memory tests.
