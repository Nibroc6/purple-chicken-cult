# Contract request p0-w01-3: e2e server on a localhost origin (WebAuthn needs a domain)

**From:** P0-W01 · **Kind:** fixture fix (frozen `web/e2e/fixtures/server.ts`)
**Implementer:** contract steward

## Why

`web/e2e/fixtures/server.ts` serves every Playwright run at
`http://127.0.0.1:<port>` and sets `PCC_ORIGIN` to it, so `PCC_RP_ID` becomes
`127.0.0.1`. Browsers refuse WebAuthn on IP-address origins: Chromium's
`navigator.credentials.create/get` throws `SecurityError: This is an invalid
domain.` (checked with the virtual authenticator of `fixtures/auth.ts`; the same
call on `http://localhost:<port>` succeeds). Every passkey journey (W01 login and
step-up, W04 join, W11 export step-up through the modal, INT-0 genesis → join)
therefore cannot run against the shared server.

Meanwhile `web/e2e/p0-w01.spec.ts` starts its own server exactly like
`startServer()` but with `PCC_ORIGIN=http://localhost:<port>` (same binary,
database and static dir that `scripts/e2e.sh` prepared; a free port), clearly
marked in the spec. When this lands the spec drops that block and uses
`baseURL`.

## Diff

`web/e2e/fixtures/server.ts`, in `startServer()`:

```ts
  const port = await freePort();
  const baseURL = `http://localhost:${String(port)}`; // WebAuthn refuses IP origins
  const child: ChildProcess = spawn(bin, ['serve'], {
    ...
    env: {
      ...process.env,
      PCC_ENV: 'test',
      PCC_TEST_HOOKS: '1',
      PCC_HTTP_ADDR: `127.0.0.1:${String(port)}`,
      PCC_ORIGIN: baseURL,
      PCC_AUTO_MIGRATE: '1',
    },
  });
  await waitReady(`http://127.0.0.1:${String(port)}`, 30_000);
```

(The server keeps listening on 127.0.0.1 only; `localhost` resolves there in
Chromium. `waitReady` probes the loopback address directly so Node's resolver
order — `::1` first on some hosts — does not matter.)
