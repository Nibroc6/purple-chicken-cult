# Contract request p1-w08-2: the media picker tests under Node 24

**Status:** applied by the contract steward (test-only) after the P1-W08 work commits.

**From:** P1-W08 · **Kind:** test-only, in a file P1-W04 owns
(`web/src/features/media/media.test.tsx`) · **Implementer:** contract steward

## Why

CI runs Vitest on Node 24 (`web/package.json` asks for `>=24`). The first CI run of
`claude/phase-1` work (PR for P1-W08) failed four upload tests there. All four had passed
locally under Node 22. The test's fetch stub reads the upload with `req.formData()`.
Node 24's undici multipart parser asserts that each file part is an instance of its own
`File` class, but in the jsdom environment the global `File` and `FormData` are jsdom's.
The parse throws, the stub never answers, and `waitFor` times out after 1 s. The product
code is not affected: browsers have one `File`.

## Diff

`media.test.tsx`: `beforeEach` stubs the globals `FormData` (undici's, obtained from a
parsed `Response`) and `File` (`node:buffer`), and `png()` builds a `node:buffer` File.
The assertions are unchanged. The test passes under Node 22 and Node 24.
