# Contract request p1-w05-1: VAPID keys for e2e runs, the subscription-state route, the push endpoint policy

**Status:** applied by the contract steward (additive) before the P1-W05 work commits.

**From:** P1-W05 · **Kind:** additive (test-fixture wiring, one route in the module's own
fragment, plan text) · **Implementer:** P1-W05

## Why

1. Push is enabled only with VAPID keys (D20), and the e2e server
   (`web/e2e/fixtures/server.ts`, scaffold-owned) starts without them, so no spec could
   ever subscribe or deliver: `/api/push/key` answers `{enabled:false}` for the whole run.
   The acceptance tests (payload text, `hide_content`, logout, endpoint reassignment) need
   a run where push is on and messages go to a **local fake push endpoint**, never to a
   real push service.
2. The subscription UI must show whether *this device* is still subscribed for *this
   account*: logout removes that session's subscription, and re-subscribing the endpoint
   from another account moves it, while the browser's `PushSubscription` stays. The three
   routes of plan §5.3 cannot answer that.
3. The VAPID sender posts to URLs supplied by clients. Without an endpoint policy it is
   an SSRF primitive (an authenticated user could make the server POST to internal
   addresses).

## Diff

* `web/e2e/fixtures/server.ts`: a fresh P-256 VAPID key pair per run (node:crypto),
  passed as `PCC_VAPID_PUBLIC`, `PCC_VAPID_PRIVATE`, `PCC_VAPID_SUBJECT` (unless already
  set in the environment). No spec subscribes unless it serves its own fake endpoint, so
  the other specs are unaffected (Notify enqueues `push.deliver` only for recipients with
  a subscription).
* Plan §5.3: `GET /api/push/subscriptions?endpoint=` → `{subscribed, hide_content}` (free,
  the caller's own rows only; unknown or foreign endpoints are `subscribed:false`).
* Plan §4.2 `platform/webpush`: the endpoint policy (https, port 443, no userinfo, no
  proxy, no redirects, public addresses only, checked on every dial; loopback on any
  port only under `PCC_ENV=test` + test hooks) and fixed-size (4096-byte) records.
