# Contract request p0-w01-1: account activation at enrollment

**Status:** applied by the contract steward (additive) at the P0-W01 merge, implemented by `gate/users` (`users/accounts.go`) and wired (`d.Accounts = a.Users`); the local adapter in `gate/auth` is gone (`loadAccount` reads `d.Accounts` + `d.Users`, `signChange` reads `ext_id` through `Account`, enrollment calls `ActivateGenesis`). Steward adaptation: `Account` takes a `forUpdate bool` so `EnrollFinish` keeps its `FOR NO KEY UPDATE` row lock on the account. coreref: `MemUsers` implements `Accounts`; coretest `NewMem` wires it.

**From:** P0-W01 · **Kind:** additive (one new interface, one optional `Deps` field, wiring)
**Implementer:** P0-W11 (`gate/users`), coreref for tests

## Why

Genesis enrollment (plan §4.7 auth `EnrollFinish`, D29) must turn a
`pending_enrollment` genesis account active and record `tos_version`,
`tos_accepted_at` and `age_attested_at`. Those `users` columns belong to W11
(plan §3.4: "users — settings, status, deletion"), and `core.Users` has no
method for it. WebAuthn ceremonies also need the account's `webauthn_user_id`
(the WebAuthn user handle), which `core.UserMeta` does not carry, and
`BindCredential` signs a `PasskeyChange` record naming the account's `ext_id`
for an account created in the **same** transaction (join), which the cached
`Users.Get` cannot see.

Meanwhile `gate/auth` uses a local adapter, clearly marked in
`internal/gate/auth/credentials.go` (`loadAccount`, `activateGenesis`, and the
`ext_id` read in `signChange`), reading `users (webauthn_user_id, handle,
display_name, status, ext_id)` and running

```sql
UPDATE users SET status = 0, tos_version = $2, tos_accepted_at = $3, age_attested_at = $3
WHERE id = $1 AND status = 1 AND is_genesis
```

inside the enrollment transaction (then `Bus.Publish(UserChanged)` after commit).
When this lands those become calls and the SQL moves to `gate/users`.

## Diff

`internal/gate/internal/core/interfaces.go` (after `DisplayNames`):

```go
// Accounts exposes the account facts auth needs inside a transaction
// (impl: gate/users). Steward: contract request p0-w01-1.
type Accounts interface {
	// Account reads the WebAuthn user handle, ext_id and status of id through q
	// (so an account created earlier in the same transaction is visible).
	Account(ctx context.Context, q store.Q, id UserID) (webauthnID []byte, ext uuid.UUID, status uint8, err error)
	// ActivateGenesis turns a pending genesis account active and records the
	// accepted terms version and the age attestation at at (D29). gate.ErrNotFound
	// unless the account is a pending genesis account. The caller publishes
	// UserChanged after commit.
	ActivateGenesis(ctx context.Context, tx store.Q, id UserID, tosVersion int, at time.Time) error
}
```

`internal/gate/internal/core/deps.go` (in `Deps`, steward additions):

```go
	// Steward additions (contract request p0-w01-1). Optional: nil until W11
	// implements it; gate/auth falls back to its local adapter.
	Accounts Accounts
```

`internal/gate/wire/wire.go`: `d.Accounts = a.Users` once `gate/users` implements it.

`internal/gate/internal/coreref/users.go`: `MemUsers` implements `Accounts`
(webauthn ID `sha256("webauthn:"+handle)` as `coretest.World` writes it; status
from the stored meta; `ActivateGenesis` flips `StatusPendingEnrollment` to
`StatusActive`).
