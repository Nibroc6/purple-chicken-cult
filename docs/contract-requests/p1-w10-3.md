# Contract request p1-w10-3: recovery hardening (owner notice, passkey veto, kept passkeys, scaled guardians)

**Status:** applied with the change that needs it.

**From:** P1-W10 follow-up · **Kind:** additive (one core interface, one `Deps` field, one
notification kind, two columns) plus one signature change in P0-W01's auth
(`EnrollFinish` loses `removeOld`) · **Files:** `internal/gate/internal/core/{interfaces.go,deps.go}`,
`internal/gate/wire/wire.go`, `internal/gate/auth/**` (P0-W01/P1-W07),
`internal/gate/notify/notify.go` and `internal/platform/i18n/catalogs/en/server.json` (P1-W05),
`api/openapi/{_common,auth}.yaml`, `web/src/features/auth/**`,
`web/src/i18n/locales/en/{auth,notifications}.json`, migration `3101_recovery_hardening.sql`

## Why

A review of guardian recovery found that any two friend+ friends could take an account over,
and keep it, if the owner did not open the app during the 24 h hold:

1. **The owner was never told.** Only friends were notified. New notification kind
   `account_recovery` (no subject; `data.reason` = `recovery_started` | `recovery_pending`)
   goes to the account when a guardian recovery is vouched for or a manual one is opened, and
   when either starts holding. Push text `push.account_recovery`.
2. **No passkey veto.** `core.RecoveryGuard.PasskeyLogin(ctx, user, credCreated)` (impl:
   gate/account) is called by `auth.LoginFinish` after the assertion verified and before the
   session is issued, in its own transaction (no credential row lock is held while it voids
   enrollment tokens). It cancels every live recovery of the account opened no earlier than
   the passkey's creation. `Deps.Recovery`; nil skips it.
3. **Recovery could delete the old passkeys.** `EnrollFinish` no longer takes `removeOld`
   (the API field is accepted and ignored). The recovered credential is marked
   (`webauthn_credentials.recovered_at`); for `auth.RecoveryLockFor` (7 days) it cannot remove
   passkeys older than itself (409 `recovery_lock`), while they can remove it.
4. **Two guardians regardless of friend count.** `recovery_requests.guardians_needed`, set
   when a guardian recovery opens: `account.GuardiansNeeded(n)` = `max(2, ceil(log2 n))`,
   capped at 5, n = the account's friend+ count. `AccountGuardianRequest` and
   `AccountRecoveryStatus` carry `approvals` and `needed`.
