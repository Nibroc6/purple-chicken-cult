## Provided by P1-W03

* **Co-signed graph changes** (`gate/friends/cosign.go`). Purposes registered with
  `core.CosignPurposes`: `friend_request` and `friend_accept` (Friendship), `unfriend`
  (Revocation), `block` (Block). The requester's verified assertion waits on the request
  (`friend_requests.draft`, `draft_assertion`); the Friendship is written at acceptance
  with both assertions (a crossed request signs the pending request's record). Blocking a
  friend signs the **Revocation** the block writes (purpose `unfriend`): a session holds
  one passkey ceremony at a time, so one change carries one co-signature. Each drafted
  record is checked against the change (people, level, author).
  * **Rule:** a session created by a passkey ceremony (`Viewer.Credential` set — every
    production user session) must co-sign; a write without a fresh assertion is the uniform
    404 and changes nothing. Credential-less user sessions exist only through the test
    hooks and keep the server-signed Phase 0 path. The Go tests of notify, tree, posts,
    feed and conformance, the INT-0 journeys and the inherited P0 specs use such sessions
    and are unchanged.
  * HTTP: optional `{intent, assertion}` body on `POST /people/{ref}/request`,
    `POST /friends/requests/{ref}/accept`, `DELETE /friends/{ref}`, `PUT /people/{ref}/block`.
    Web: the people feature asks `GET /api/auth/passkeys` whether the session's own
    credential is listed (`current`) and then opens the co-sign dialog first.
* **Hide-via** (`PUT/DELETE /people/{ref}/hide-via`, `Friends.HideVia`): friends only (the
  first hop, §4.4); writes `hide_via`, `Graph.SetHideVia` (epoch bump on add), publishes
  `HideViaChanged`. Transit only: the hidden friend and their posts stay. Fixtures take
  `"hide_via": [[user, via]]`.
* **Friend+ upgrade opener** `POST /friends/{ref}/upgrade` → `core.Handshakes.OpenUpgrade`;
  the person page renders `HandshakeHost`. `web/e2e/p1-w03.spec.ts` runs the upgrade end
  to end (the spec P1-W02 deferred): bob's session and passkey move into the camera browser
  through CDP `WebAuthn.getCredentials`/`addCredential`.
* **Lazy search** behind `PCC_LAZY_BFS=1` (`gate/graph/lazy.go`): per-reader cache keyed by
  `(viewer, epoch)` + the reader's exclusions (30 min; a day once the deep tiers ran);
  layers 2–3 on demand; layers ≥ 4 in one go, released at a whole multiple of
  `graph.DeepBucket` (600 ms) and counted as `graph.deep_search{count}`. Tests turn it on
  with `(*graph.Graph).SetLazy(true)` and `SetDeepRelease(0, nil)`.

## Follow-ups

* **INT-1 (conformance, INT-owned):** extend the noninterference/conformance generators to
  the P1 graph facts — friend+ edges (and `friend_plus` posts), the reader's hide-vias and
  other people's hide-vias (must change nothing for the reader) — and run the suite once
  more with `PCC_LAZY_BFS=1` (`wiretest.WithEnv("PCC_LAZY_BFS", "1")`, deep release set to
  0 so the suite stays fast). `gate/visibility/p1_test.go` already checks full and lazy
  against the reference on random worlds with these facts.
* **INT-1 (records):** with `Records.EnforceCosign` set, Friendship/Revocation records
  written by credential-less (test-hook) sessions are unattested by design; the Block
  record of a block of a friend is author-signed without an assertion (exports do not
  require one for Block). The invites module writes friend+ Friendship bodies with
  `"level": "friend+"`, friends writes `"friend_plus"` — pick one spelling for the record
  grammar.
* **P1-W07 (padding):** the deep-tier release (600 ms buckets inside the search) is
  independent of the route padding; a deep feed page can therefore take a further route
  bucket. Fine for H(V), but the latency histogram assertion should expect it.
* **P1-W08 (feed):** with the lazy search, `Search.Layer(k)`/`LayerBitmap(k)`/`Dist(u)` for
  k ≥ 4 (or an author beyond tier 3) block until the deep tiers are released; the first
  call pays it once per (reader, epoch) per day. `MaxLayer()` completes the search, so the
  planner should not call it before the reader reaches tier 4 if it wants laziness.
