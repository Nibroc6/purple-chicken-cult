## Provided by P1-W11

* **Preview images** (`gate/previews`, migration `3110_preview_images.sql`):
  the page's `og:image | twitter:image`, resolved against the final URL and canonical
  (`urlx.Canonicalize`), is cached with the page (`link_fetch_cache.image_url`) and fetched by
  the server for **each post** with `safefetch.GetImage` (same SSRF policy; `image/png|jpeg|
  gif|webp|avif` only, never SVG; at most `previews.MaxImageBytes` = 5 MiB, refused rather than
  truncated; within the image host's limiter budget), then handed to `Media.Ingest`. A clean
  image's media id goes to `link_previews.image_media_id`; anything else (media disabled,
  fetch failure, wrong type, `media_rejected` from a scan match or a scanner failure) leaves it
  NULL and the text preview still shows. With media disabled no image is fetched at all.
  Every post ingests its own copy (`media.source_post`), so deleting a post deletes its
  image and URL checks follow that post's visibility.
* **GFM tables** in `mdscan` and `web/src/markdown` with one rule set (a stricter subset of
  GFM so goldmark and markdown-it cannot disagree): top level only, header and delimiter rows
  start with `|`, at most `MAX_TABLE_COLS` = 10 columns, body rows end at a blank line, a block
  that may interrupt a paragraph, or a setext underline. Shared fixtures:
  `testdata/markdown/tables.json` (48 cases, shapes plus links and mentions with offsets). A
  differential run of 35,000 random table-shaped bodies through both parsers found no
  disagreement. `parse()` yields a new block `{ t: 'table', align, rows }` (rows[0] is the
  header), rendered by `<Markdown>` as a focusable, horizontally scrolling region.

## Follow-ups

* **P1-W12 (posts, views):** render `PreviewView.image` from `link_previews.image_media_id`
  via `Media.Views` and map it in `features/post/vm.ts` (agreed with P1-W12: W11 does not
  render images in `markdown/LinkPreview.tsx`). Excerpts in `gate/views` (context rows)
  strip Markdown with regexes that do not know tables, so a table's pipes and delimiter row
  show up in an excerpt; consider dropping delimiter rows and pipes there. Any layout that
  switches over `Block['t']` itself must handle `'table'`.
* **P1-W04 (media):** an edit rebuilds the previews and ingests the new image; the superseded
  preview media of the earlier version stays (unreferenced, never shown) until the post is
  deleted. `media.process` could also delete `source_post` media that no `link_previews` row
  references. `Ingest` scans an image even when the linking author's account is already held
  (uploads of a held account are refused); decide whether a held account's preview images
  should be refused too.
* **INT-1:**
  * Journey: post a link whose page has an `og:image`, a friend sees the image through a signed
    media URL (once P1-W12 renders it), unfriend → URL 404. `web/e2e/p1-w11.spec.ts` already
    checks that only the server contacts the site and that a blocklisted image is held.
  * Pre-existing (P0) disagreement found by the differential run, unrelated to tables: a link
    reference definition followed directly by a line indented 4+ columns. goldmark keeps the
    line as paragraph text (CommonMark), markdown-it starts an indented code block, so a URL or
    mention on that line is counted by the server only. Example:
    `"[r]: https://ref.example\n    https://x.example @a"`.
