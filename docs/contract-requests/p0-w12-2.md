# Contract request p0-w12-2: forget the rate counters' memory on test reset

**Status:** applied by the contract steward (additive, wiring only).

**From:** P0-W12 · **Kind:** additive (wiring in `gate/wire`, scaffold-owned)

## Why

`gate/limits` keeps a write-through cache of `rate_counters` (keyed by user, bucket and
window), the last write time per user and write kind (minimum spacing) and the anonymous
per-prefix counters (memory only by design: no IPs at rest). `Hooks.Reset`
(`/api/_test/reset`) truncates `rate_counters` with `RESTART IDENTITY`, so the next spec of the
same e2e run reuses the same user IDs; a cached count left from the previous spec would charge
a new account for a different person's requests, and the anonymous counters would carry over
every earlier spec's logins and joins. A reset should leave no limiter state behind, as a
restart would.

## Diff

`internal/gate/wire/hooks.go`, in `Reset`, next to the other in-memory resets:

```go
h.a.Limits.Reset()
```

`(*limits.Service).Reset` drops the counter cache, the spacing clocks and every anonymous
bucket (the scaffold stub gets a no-op `Reset` so this compiles before W12 lands).
