# Contract request p0-w03-1: wire friend-request state into views

**Status:** applied by the contract steward (additive): `gate/wire` assigns `d.Requests = a.Friends`.

**From:** P0-W03 · **Kind:** additive (wiring only)

## Why

`gate/views` fills `PersonView.Request` from `d.Requests` (contract request p0-w02-1), and
treats nil as "no request". `*friends.Service` now implements `core.RequestStates`, but
`gate/wire` (scaffold-owned) never assigns the field, so the running app never shows
"request sent" / "wants to be your friend" on person views: a suggestion card keeps
offering "Add friend" after the request went out, and the person page offers no
Accept / Decline. The WP's Go tests set the field by hand; the e2e spec needs the real
wiring.

## Diff

`internal/gate/wire/wire.go`, next to the other `d.* = a.*` assignments:

```go
d.Requests = a.Friends
```

Nothing else changes: `core.Deps.Requests` already exists, and `coretest.NewMem` keeps
`coreref.MemRequests`.

## Follow-up (not requested now)

`friends.PersonPosts` lists only the feed window (`PostIndex.Recent`) because no core
interface lists an author's older posts and `posts` is read only by `gate/postindex`.
When W05 lands, an optional `AuthorPosts` interface (impl: `gate/postindex`) would let
the person page page through posts of any age (plan §4.7: "any age, visible only").
