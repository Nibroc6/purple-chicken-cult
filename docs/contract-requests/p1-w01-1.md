# Contract request p1-w01-1: co-sign purposes, the signup ceremony, assertion drafts

**Status:** applied by the contract steward (additive) before the P1-W01 work commits.
`gate/users` (P1-W10) carries a one-line steward body honouring `NewUser.ExtID`; W10
owns and may restyle it. coreref: `MemCosign.RegisterPurpose`, `MemUsers` honours `ExtID`.

**From:** P1-W01 · **Kind:** additive (two new interfaces, two new `Deps` fields, two
optional struct fields, one pure helper, wiring)
**Implementer:** P1-W01 (`gate/cosign`) · **Callers:** P1-W02 (invites), P1-W03 (friends),
P1-W06 (moderation), P1-W07 (auth), P1-W10 (account)

## Why

1. `Cosign.BeginIntent(ctx, v, purpose, target)` must return the record being signed
   (`Intent.Record`, shown in the co-sign dialog) and a challenge over its **draft**
   (security #10), but only the calling module knows the record shape. Callers register a
   builder per purpose; an unregistered purpose fails closed (`ErrNotFound`).
2. The record and the assertion must verify offline (security #5). A record can be co-signed
   by several people, each over their own intent (own nonce), so the stored body cannot be
   any one draft. Each attached assertion therefore carries the exact draft it signed
   (`Assertion.Draft`); stripping the draft's `cosign` member yields the stored body.
3. The invitee signup ceremony (fidelity #21) runs in a **guest** session with a credential
   that is not yet bound to a committed user, so `Passkeys.VerifyAssertion` (viewer's own
   bound credentials, user sessions only) cannot serve it. `SignupCosign` verifies one get
   assertion with the new credential over a bundle of drafts inside the RegisterFinish
   transaction; failure aborts it.
4. The drafts the invitee signs name the invitee, so the ext_id is reserved before the
   transaction (`NewUser.ExtID`).
5. Co-sign drafts nest their nonce and issue time (`"cosign": {"nonce", "issued_at"}`) so a
   record's own `issued_at` (Invite) never collides with them (`coreref.DraftRecord`,
   `coreref.DraftMember`).

## How callers use it

```go
// Init:
d.CosignPurposes.RegisterPurpose("block", core.RecBlock, func(ctx context.Context, v core.Viewer, target gate.Ref) (any, error) {
	// resolve target (ErrNotFound on failure) and return the exact body that will be signed
})
// Handler path (intent and assertion come from the client's co-sign dialog):
err := d.DB.Tx(ctx, func(tx pgx.Tx) error {
	a, _, err := d.Cosign.Require(ctx, tx, v, "block", core.RecBlock, body, intent, assertion)
	if err != nil { return err }
	hash, err := d.Signer.Sign(ctx, tx, core.RecBlock, v.ID, body, parties, a) // body: the SAME value the builder returned
	…
})
```
The body passed to `Require` must canonicalize to the body the builder produced at Begin
(timestamps included), else `ErrNotFound`. A caller whose body has a time of its own may
pass `body == nil` instead: `Require` then binds to the stored draft, and
`Signer.Sign(ctx, tx, kind, author, nil, parties, a)` stores the body taken from
`a.Draft` (the draft minus its `cosign` member). Either way the caller re-checks its own
state (still friends, not yet blocked, …) inside the same transaction.

Signup (P1-W02, `RegisterFinish` split in two requests):
`register/finish {credential}` → `FinishRegistration` → reserve `ext_id` → `BeginSignup(sess,
cred, [{RecInvite, invite}, {RecFriendship, friendship}])` → `{options, records}`;
`register/cosign {assertion}` → serializable tx: `Users.Create(… ExtID)` → `BindCredential`
→ `FinishSignup(tx, sess, uid, cred, same recs, assertion)` → `Signer.Sign(…, as[0])`,
`Signer.Sign(…, as[1])` → … → commit. A failed `FinishSignup` returns the error, so the
transaction rolls back and nothing is created.
