# Contract request p0-w07-1: forget the feed sessions on test reset

**Status:** applied by the contract steward (additive, wiring only).

**From:** P0-W07 · **Kind:** additive (wiring in `gate/wire`, scaffold-owned)

## Why

`gate/feed` keeps every feed session (tier snapshots, the seen set and show-less counts read
at session start, the per-snapshot memo) in memory, keyed by `(viewer, random session id)`
(plan §3.2 "not stored", D5). `Hooks.Reset` (`/api/_test/reset`) truncates every table with
`RESTART IDENTITY`, so the next spec of the same e2e run reuses the same user IDs for new
accounts. A session left over from the previous spec is unreachable without its own cursor,
but it still counts against the viewer's five live sessions and, when it is finally evicted,
reports a `feed.tier_reached` bucket for a world that no longer exists. A reset should leave
no feed state behind, exactly as a restart would.

## Diff

`internal/gate/wire/hooks.go`, in `Reset`, after the caches are reloaded (before the graph
load):

```go
h.a.Feed.Reset()
```

`(*feed.Service).Reset` drops every session without reporting metrics. Nothing else in the
feed module is cached.
