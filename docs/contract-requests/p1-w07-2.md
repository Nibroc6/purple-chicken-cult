# Contract request p1-w07-2: the P0 passkey-add helper of P1-W01's chain test

**Status:** applied by the contract steward (test-only) after the P1-W07 work commits.

**From:** P1-W07 · **Kind:** test-only, in a file P1-W01 owns
(`internal/gate/cosign/verify_test.go`) · **Implementer:** contract steward

## Why

From P1-W07 a session created by a passkey ceremony must co-sign its passkey changes
(hand-off p1-w01-2): `AddPasskeyFinish` verifies the new credential and parks it until an
existing passkey co-signs its `PasskeyChange` record, so it gained the co-signature
arguments and a result: `AddPasskeyFinish(ctx, body, name, intent, assertion)
(AddPasskeyResult, error)`. `TestPasskeyChangeChain` used the old three-argument call from
an enrolled (passkey) session to produce an unattested add after the co-sign cut-over —
the package no longer compiles, and in a passkey session that unsigned add can no longer
happen at all (which is the point of the change).

The unsigned Phase 0 path still exists for credential-less sessions (test hooks), and that
is exactly the case the test means ("the P0 add flow (no co-sign) after the cut-over
breaks the chain"). The helper now runs it there; the assertion is unchanged.
