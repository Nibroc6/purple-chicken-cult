# Contract request p0-w08-1: forget the tree snapshots on test reset

**Status:** applied by the contract steward (additive, wiring only).

**From:** P0-W08 · **Kind:** additive (wiring in `gate/wire`, scaffold-owned)

## Why

`gate/tree` keeps every opened tree (ranked rows, the rows on screen, the show-less counts
and first-hop edge ages read at open time, the per-snapshot memo) in memory, keyed by
`(viewer, random snapshot id)` (plan §3.2 "not stored", D5), exactly like the feed sessions
of p0-w07-1. `Hooks.Reset` (`/api/_test/reset`) truncates every table with
`RESTART IDENTITY`, so the next spec of the same e2e run reuses the same user and post
numbering. A snapshot left over from the previous spec is unreachable without its own id,
but it still counts against the viewer's ten live snapshots. A reset should leave no tree
state behind, exactly as a restart would.

## Diff

`internal/gate/wire/hooks.go`, in `Reset`, next to `h.a.Feed.Reset()`:

```go
h.a.Tree.Reset()
```

`(*tree.Service).Reset` drops every snapshot. Nothing else in the tree module is cached.
