# Contract request p0-w05-1: wire the post index's mentions, reload it on test reset

**Status:** applied by the contract steward (additive, wiring only).

**From:** P0-W05 · **Kind:** additive (wiring in `gate/wire`, scaffold-owned)

## Why

* `gate/views` fills `PostView.Mentions` from `d.Mentions` (contract request p0-w02-1) and
  treats nil as "no mentions". `*postindex.Index` now implements `core.MentionIndex` over the
  `mentions` table that `gate/posts` writes, but `gate/wire` never assigns the field, so the
  running app never links a mention. p0-w02-1 already planned this line for W05's merge.
* `Hooks.Reset` (`/api/_test/reset`) truncates every table and reloads the users cache and
  the graph, but not the post index. With the real index (window posts in memory, metadata
  and links in LRUs) a reset that is not followed by a seed leaves posts in memory that no
  longer exist in the database; the next post that references one fails on a foreign key.
  The coreref stub had the same gap, but nothing exercised it before W05.

## Diff

`internal/gate/wire/wire.go`, with the other `d.* = a.*` assignments:

```go
d.Mentions = a.PostIndex
```

`internal/gate/wire/hooks.go`, in `Reset`, between the users reload and the graph load:

```go
if err := h.a.PostIndex.Load(ctx); err != nil {
	return err
}
```

`(*postindex.Index).Load` replaces the in-memory window with what the database holds and
empties every cache. Nothing else changes: coretest keeps `coreref.MemPosts` for memory
tests.
