# Contract request p1-w08-1: the save action, and Top accepted as a saved preset

**Status:** applied by the contract steward before the P1-W08 work commits.

**From:** P1-W08 · **Kind:** additive (one optional `PostActions` member) plus a one-line
lift in files P1-W10 owns (`internal/gate/account/settings.go`, its tests, `web/e2e/p0-w11.spec.ts`,
`web/src/features/settings/{vm.ts,DisplayPage.tsx}`, `settings.json`)
· **Implementer:** contract steward · **Callers:** every format (cards, compact, explorer)

## Why

1. P1-W08 adds the private save (ARCHITECTURE §5.2). The control lives in the engage bar,
   which is pure over the view-model and `PostActions` (no API import), so the action has
   to travel in `PostActions` like `like` does. It is optional, as `markSeen` is, so a
   layout or a test that builds its own actions keeps compiling, and the engage bar shows
   the control only when the action is there. The state is the existing
   `PostVM.savedByMe`.
2. P1-W08 lifts `preset_unavailable` for Top (plan §P1-W08). The feed and the tree are
   W08's, but the saved preset is validated by `account.UpdateSettings` (P1-W10), which
   still rejects `top` as Phase 1. The feed's preset switch saves the choice there, so
   without the lift Top would be served but never remembered. W10 has not started; the
   lift is the one condition, its test case and the settings page's third choice.
