# Contract request p0-w07-2: the "why" loader injected into the integrity components

**Status:** applied by the contract steward (additive, types + one context).

**From:** P0-W07 · **Kind:** additive (`web/src/integrity/types.ts`, scaffold-owned contract)

## Why

Plan §6.2 gives the WhyButton integrity component only `{ post: Ref }` and says it "fetches
`/posts/{ref}/why` lazily through an injected loader", but the contract names neither the
loader nor the view-model it returns. Formats and integrity components may not import
`src/api` (ESLint), so the feature that owns the endpoint (feed, P0-W07; the tree reuses it,
P0-W08) must hand the loader down, and W10 must be able to read it without importing a
feature. Without a shared name each side would invent its own.

## Diff

`web/src/integrity/types.ts` (re-exported by `integrity/index.ts` through `export *`):

```ts
import { createContext } from 'react';
import type { ChainVM, InviterVM, PostVM, Preset, Ref } from '../vm/types';

// "Why am I seeing this?" (§5.3): GET /posts/{ref}/why mapped by the owning feature.
export type WhyReason =
  | 'network_likes' | 'below_author_usual' | 'reply_penalty' | 'good_replies'
  | 'cold_start' | 'show_less' | 'chronological';
export interface WhyVM {
  tier: number;
  via: ChainVM;
  postedAt: Date;
  preset: Preset;
  shiftMinutes: number; // how far ranking moved the post; positive = up
  reasons: WhyReason[];
}
export type WhyLoader = (post: Ref) => Promise<WhyVM>;
// Provided by the page that owns the posts (feed, tree); WhyButton reads it. Undefined
// outside such a page (the button then has nothing to load).
export const WhyLoaderContext = createContext<WhyLoader | undefined>(undefined);
```

The feed page (P0-W07) provides `WhyLoaderContext` around its layout with a loader over
`GET /api/posts/{ref}/why`; P0-W10 makes `WhyButton` open a panel that calls it lazily.
