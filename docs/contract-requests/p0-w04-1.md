# Contract request p0-w04-1: handle rules for the join flow

**Status:** applied by the contract steward (additive): new interface `core.HandleRules`,
new field `core.Deps.Handles`, implemented by `gate/users`, wired in `gate/wire`.

**From:** P0-W04 · **Kind:** additive (new interface, new optional Deps field)

## Why

`RegisterBegin` (plan §4.7 invites) must answer `handle_invalid` and `handle_taken` before
it starts the passkey ceremony, so the invitee never creates a passkey for a handle that
cannot be registered. The handle rules (NFKC, lowercase, `^[a-z0-9_]{3,20}$`, reserved list)
live in `gate/users` (`users.Canon`, `users.Reserved`), which `gate/invites` may not import
(archtest A8). `core.Users.HandleAvailable` takes an already canonical handle, so the join
flow has no way to produce one. Copying the reserved list into `gate/invites` would let the
two lists drift.
