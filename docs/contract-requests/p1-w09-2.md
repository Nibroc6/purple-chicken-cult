## Themes

- **Shape.** `PUT /api/me/theme {tokens}`: a complete palette of eight `#rrggbb` colors (`bg`,
  `surface`, `text`, `muted`, `accent`, `border`, `integrity_bg`, `integrity_text`) plus
  optional `radius` (0–24 px), `density` (`compact` | `comfortable` | `spacious`), `font`
  (allowlist: `system`, `serif`, `humanist`, `rounded`, `mono`, `hyperlegible`; local font
  stacks only) and `font_size` (14 px floor to 24). `GET` (contract request p1-w09-1) answers
  `{theme}` or `{}`; `DELETE` goes back to the default.
- **Rules** (`internal/gate/themes/tokens.go`): integrity text on integrity background ≥ 4.5:1
  (every integrity element paints that pair, so this is the tier-header rule), integrity text
  against the card and the page ≥ 3:1 (button outlines), body text, muted text and links
  ≥ 4.5:1 on both backgrounds. A failure is `theme_contrast` with `field` naming the color.
- **Presets** live in `web/src/features/themes/presets.json`; the Go test runs every one through
  `Validate`, the Vitest suite through the client mirror, and `p1-w09.spec.ts` measures the
  seven integrity elements on a feed card under each. **INT-1's visibility/contrast pass**
  (`web/e2e/integrity.spec.ts`) can iterate the same file: `PUT /api/me/theme` with a preset's
  tokens, reload, measure.
- **The accessibility switches win:** with `data-contrast="high"` the theme's colors are not
  applied (its radius, spacing and font are), a text size other than normal drops the theme's
  font size, the dyslexia font drops its font. The applier (`features/themes/slots.tsx`)
  re-applies when those attributes change.
- A theme is one palette: it applies in both color schemes. The default (no theme) keeps the
  light / dark tokens of `styles/tokens.css`.
- Theme properties are set through the CSSOM on `<html>` (`style.setProperty`), which
  `style-src 'self'` allows; nothing builds a style attribute or a stylesheet.

## Explorer

- `ui_prefs.format = "explorer"` is valid now (p1-w09-1). Feed: the Cards card with a tree
  thumbnail beside it (`explorer-card`, `explorer-thumb`; parents counted from the card's
  `context` rows of kind `ref`, replies from `reply_count`). The card itself is Cards'
  `PostLayout`, so its `article` says `data-format="cards"`; the feed and tree containers say
  `explorer`. **P1-W12:** media rendered in the Cards card shows in Explorer with no change.
- Tree: `explorer-canvas` (SVG, `role="img"`, focusable for keyboard pan and zoom) over the
  Compact outline (`Outline` in `formats/compact/TreeLayout.tsx`, now with an optional
  `control` so another view can own each row's centered post and a selection). Clicking a node
  in a row at `gen ≥ -1` re-centers it (`actions.recenter`), as swiping does in Cards.
- **Minimap:** shown when the canvas is zoomed below 100 % on a viewport at least 64rem wide,
  hidden from assistive technology (the outline is the accessible view). The Cards rows layout
  has no minimap; if INT-1 reads §10.1.4's "zooming out shows a minimap" as also meaning the
  Cards tree, `formats/explorer/canvas/Minimap.tsx` takes any `CanvasLayout`.
